# po4yka.dev

Personal portfolio, apps showcase, and bilingual (en/ru) technical blog. Astro 7 islands (React 19, Tailwind CSS 4, Motion) prerendered as static pages, plus a server-rendered admin SPA and API on Cloudflare Workers + D1.

This file is the single source of agent instructions for Codex and Claude Code (`CLAUDE.md` imports it). Canonical design and product docs live in `DESIGN.md` and `docs/Guidelines.md`.

## Commands

- `npm test` (Vitest, Node env) — run a single file with `npx vitest run <path>`. Tests live in `src/__tests__/`; D1 and API-context mocks are in `src/__tests__/helpers.ts`; `cloudflare:workers` is aliased to a mock in `vitest.config.ts`. There is no DOM test environment, so React components are covered by Playwright (`npm run test:e2e`) instead.
- `npm run typecheck` runs TypeScript 6 (`tsc6`), TypeScript 7 (`tsc`), then `astro check`. Both compilers must pass; the TS6 bridge is temporary but still enforced.
- `npm run dev` for local work; `npm run build && npm run preview` to check production output (Playwright runs against the preview server). `npm run build` runs `generate:all` first, then `astro build`.
- `npm run lint`.
- `npm run generate:all` regenerates every derived data file; `npm run validate:all` checks generated files against their sources.
- `npm run validate:skills` checks agent skill layout and routing policy (see Skills below).

Match verification to the change: the affected test file and `npm run typecheck` for most code edits; add `npm run build` when touching content, generators, routing, Astro config, or SEO surfaces; check visual changes in a browser at mobile and desktop widths. CI (`.github/workflows/ci-cd.yml`) runs lint, typecheck, tests with coverage thresholds, build, Playwright, and Lighthouse on pushes and pull requests to `main`.

## Content pipeline

- Canonical sources: MDX in `src/content/blog/{en,ru}/<slug>.mdx` (same slug for both languages), `src/content/projects.json`, `src/content/experience.json`.
- Generated, never hand-edited: `src/data/{blogData,blogMeta,projectsData,experienceData,changelog,buildMeta}.ts` and `db/seed.sql`. Edit the source and run the generator. The build regenerates these files, so a manual edit is silently lost at deploy (Claude Code also has a pre-edit hook that blocks it).
- Client islands import post metadata from `blogMeta.ts` (`blogPostsMeta`), never from `blogData.ts`, so article bodies stay out of the browser bundle.
- `changelog.ts` and `buildMeta.ts` come from git history and refresh only in CI or with `BLOG_REFRESH_BUILD_META=1`. The public `/changelog` lists only `feat`, `fix`, and `perf` commit subjects (grouped per day), so write those subjects for readers.
- MDX frontmatter needs ISO `publishedAt` (`"2026-04-01"`) plus the display label `date` (`"Apr 2026"`); add `updatedAt` when revising a published post.
- Some long-form posts are generated by `python3 scripts/sync_to_blog.py` in the sibling `havamal/` repo from `havamal/articles/<slug>/ARTICLE.md`. The sync owns those MDX files: edit the havamal source and re-run the sync, or the next sync overwrites the change (see `havamal/AGENTS.md`, section "Sync to Blog").

## Server, admin, and data

- API routes live in `src/pages/api/` and must `export const prerender = false`.
- Admin routes wrap handlers in `withAdmin({ capability, schema? }, handler)` from `src/lib/admin-handler.ts`, which handles origin check, session auth, capability scoping, Zod validation, and JSON errors. Do not call `requireAuth()` inside `withAdmin` handlers. Standard CRUD entities are declared once with `defineCollection()` in `src/lib/collections/`.
- D1 is reached through `import { env } from "cloudflare:workers"` (`env.DB`), not `locals.runtime`. Sessions are HttpOnly cookies; auth is passkey-first (`@simplewebauthn/*`) with password fallback gated by `ADMIN_PASSWORD` + `ALLOW_PASSWORD_LOGIN`.
- Schema is in `db/schema.sql`; schema changes need a new numbered file in `db/migrations/`. JSON arrays (tags, platforms, links) are stored as TEXT and parsed in the data layer.
- Admin SPA: `src/admin/` (React Router, TanStack Query with keys in `src/admin/hooks/useAdminQueries.ts`). Visitor preferences: Zustand store in `src/stores/settingsStore.ts`.

## Design

Before visual or copy changes, read `DESIGN.md` (tokens, components, motion rules, deleted components) and `docs/Guidelines.md` (intent, tone, anti-slop rules). `DESIGN.md` wins where they differ. The rules most often broken:

- No chromatic accent. Emphasis is `--emphasis` (white on dark, black on light) plus weight and underline; `--destructive` is only for destructive actions.
- Fonts: Geist Sans for chrome and all headings, Geist Mono only for code, terminal output, and `.label-meta`, Piazzolla only for blog prose and blog titles (`.display-serif`).
- Flat panels: 2px radius, 1px `var(--border)`, no shadows, no gradients, no glassmorphism, no pill buttons.
- No fabricated data: if a panel has no real data source it does not exist, and terminal output shows real data, never invented logs or metrics.
- Motion is limited to the permitted list in `DESIGN.md` (fades, opacity and background shifts, underline and rule draws, a few named keyframes); no `whileTap`/`whileHover` geometry changes, no pulse loops; respect reduced motion.
- Content must be in the static HTML; islands are for interactive chrome only (AI crawlers do not run JavaScript).

Third-party design skills (Impeccable, taste, UI/UX Pro Max, Hallmark, Vercel) and the superseded `signal-deck` skill give generic or outdated advice. Where they conflict with the rules above, the project docs win: this is Astro with React islands (ignore Next.js/RSC guidance), icons are `lucide-react`, and no new fonts or palettes.

## SEO and agent-discoverability surfaces

These are load-bearing; keep them working when changing pages, layouts, or content:

- `public/robots.txt` (per-bot rules; admin disallowed for all), `public/llms.txt` (hand-written), `src/pages/llms-full.txt.ts`.
- Raw markdown endpoints `src/pages/blog/[slug].md.ts` and `src/pages/blog/ru/[slug].md.ts`; RSS `src/pages/rss.xml.ts` and `src/pages/rss.ru.xml.ts`.
- JSON-LD in `src/components/JsonLd.astro` and `src/components/ProjectsJsonLd.astro` (ISO dates, `inLanguage`, `wordCount`, `mainEntityOfPage`).
- `src/layouts/BaseHead.astro` owns canonical, OG/Twitter tags (including `og:locale` and `og:site_name`), RSS links, and `hreflang` + `x-default` on every post; pages without a per-post image fall back to `/og-default.png`.
- Per-post OG images are rendered at build time by `scripts/generate-og-images.ts` (Satori + Resvg; Workers cannot render them at runtime).
- `src/components/BlogPostIsland.tsx` keeps `<article>` > `<header>` > `<h1>` + `<time dateTime>`; the admin layout keeps `noindex,nofollow`.

A new page type or content collection should get a JSON-LD node, an `llms-full.txt` entry, a `.md` variant, and a sitemap entry where they make sense.

## Boundaries

Local, reversible work (edits, tests, builds, generators, local D1 with `--local`) needs no confirmation. Ask first before:

- anything that lands on `main` (push, PR merge, enabling auto-merge): CI deploys `main` to production at po4yka.dev;
- anything against remote Cloudflare resources (`wrangler deploy`, `wrangler d1 ... --remote`, secrets);
- rewriting published history, force-pushing, or deleting branches;
- commands that publish or notify externally: `npm run indexnow`, `npm run lighthouse` (uploads reports to public temporary storage).

Commits follow Conventional Commits (enforced by commitlint in the `commit-msg` hook). No emoji in code or docs.

## Skills

Repository skills live in `.agents/skills/` (read by Codex). Claude Code reads `.claude/skills/`; for skills this repo owns, those entries are symlinks to `.agents/skills/`, so edit the `.agents/skills/` copy. Vendored skills are refreshed by `scripts/update-*.sh` or the `skills` CLI (`skills-lock.json`); do not hand-edit them, and re-run `bash scripts/apply-skill-policy.sh` after updating. That script marks design skills whose defaults contradict `DESIGN.md` as explicit-invocation only.
